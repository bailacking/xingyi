# 主题规范

主题**不重写界面**，只做两件事：改 Token、挑组件变体。这是一个人维护还能做到"深度个性化"的唯一办法。

从 W4 起主题可以**打包分享**：导出 zip → 发给别人 → 设置页导入。

---

## 一、主题包结构

```
my-theme/
├─ theme.json         必需：token + 元信息
└─ assets/            可选：只允许图片
   ├─ board.png
   └─ stone.png
```

| 允许 | 禁止 |
|---|---|
| `theme.json`（根目录，唯一） | **CSS**（`style.css` / `.scss` / `<style>`） |
| `assets/` 下的 `png` / `jpg` / `jpeg` / `webp` | **JS**（`.js` / `.mjs` / `.cjs` / `.ts` / `.tsx`） |
| | `.html` / `.svg` / `.xml` / 可执行文件 / 其它任意类型 |
| | 绝对路径、`..` 越界、加密 zip、分卷 zip、ZIP64 |

**导入时的限制**：zip ≤ 5 MB · 文件数 ≤ 20 · 单文件解压后 ≤ 8 MB · 全部解压后 ≤ 20 MB。

> 为什么要卡这么死：主题是全社区分享的文件，等于把「别人写的文件」放进你的程序目录。
> 只允许 json + 图片，且**服务端从不解析、从不执行、从不注入任何 CSS/JS**，是这个功能的底线（AGENTS.md I8）。
> 代价是主题能改的东西变少了——但换来的是「随便下载一个主题包也不会中招」。

多层根目录（资源管理器「压缩到 zip」会自带一层 `my-theme/`）会自动剥掉，不用手动整理。

## 二、theme.json

```json
{
  "id": "walnut",
  "name": "胡桃木",
  "author": "xingyi",
  "version": "1.0.0",
  "description": "米白、深胡桃木、细金线。",
  "builtin": true,
  "tokens": {
    "color": {
      "bg": "#F7F4EE",
      "surface": "#FFFDF9",
      "surfaceAlt": "#F1EBE0",
      "primary": "#3E2C20",
      "accent": "#A98C5F",
      "text": "#2A2622",
      "textDim": "#6B625A",
      "line": "#DCD2C2",
      "board": "#E5C08A",
      "boardEdge": "#C79E67",
      "boardLine": "#4A3A2A",
      "blackStone": "#15110E",
      "whiteStone": "#FCFAF5",
      "seal": "#9C3A2E",
      "sealText": "#FBF7F2",
      "danger": "#B4432F",
      "ok": "#4E7A52"
    },
    "radius": { "sm": 2, "md": 4, "lg": 6 },
    "shadow": 0,
    "density": "comfortable",
    "motion": { "speed": 200, "bounce": false },
    "font": { "title": "serif", "body": "system-ui" },
    "decor": [],
    "playerMark": "seal"
  },
  "variants": {
    "button": "flat",
    "panel": "paper",
    "playerMark": "seal",
    "result": "plain"
  }
}
```

### 元信息

| 字段 | 约束 | 说明 |
|---|---|---|
| `id` | `^[a-z0-9][a-z0-9_-]{0,31}$` | 目录名 = id；不能用 `walnut` / `youth` / `bamboo`（内置）。不写则按 `name` 生成 |
| `name` | 必填，≤ 40 字 | 设置页卡片标题 |
| `author` / `version` / `description` | 可选 | 缺省为 `匿名` / `1.0.0` / 空 |
| `builtin` | 导入时**强制 false** | 内置主题只认仓库里的 `data/themes/<id>/theme.json` |

### token 白名单（只认这些键）

| 组 | 键 | 取值 |
|---|---|---|
| `color` | bg surface surfaceAlt primary accent text textDim line board boardEdge boardLine blackStone whiteStone seal sealText danger ok | **只能是 `#rgb` / `#rgba` / `#rrggbb` / `#rrggbbaa`** |
| `radius` | sm md lg | 0~64 整数（px） |
| `shadow` | — | 0~3 整数（0 几乎无阴影，3 柔光） |
| `density` | — | `comfortable` / `compact` |
| `motion` | speed / bounce | speed 0~2000 整数（ms）；bounce 布尔 |
| `font` | title / body | 字体族字符串，≤ 160 字；**不允许括号、分号、`@`、`url(`** |
| `decor` | — | `[]` 或含 `glow` / `particles`；性能不达标时自动关 |
| `playerMark` | — | `seal` / `avatarCard`（目前只有 `seal` 有实现） |

`variants`：`button` = `flat/soft/glow` · `panel` = `paper/glass/solid` · `playerMark` = `seal/avatarCard` · `result` = `plain/card`。

### 三种处理方式

| 情况 | 行为 |
|---|---|
| **缺字段** | 用默认值（= 胡桃木）补齐，照常导入 |
| **不认识的字段** | 忽略，并在导入结果里提示「已忽略不认识的字段 X」 |
| **值不合法**（`#000; } body{...}`、`shadow: 9`、`font: url(x)`） | **整个包拒绝**，返回中文原因并指出字段名 |

值不合法就整包拒绝，而不是「悄悄换成默认值」——否则作者会以为自己的主题生效了，实际半坏。
颜色只允许十六进制，就是为了不给 CSS 函数留任何入口。

## 三、HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/theme` | 列表（内置 + 已导入），含 tokens / variants / assets 的 URL |
| POST | `/api/theme/import` | body = zip **原始字节**，`content-type: application/zip` → `{ theme, warnings }` |
| GET | `/api/theme/:id/export` | 下载 zip（`content-disposition: attachment`） |
| GET | `/api/theme/:id/asset/:file` | 主题包里的图片（png/jpg/webp，文件名白名单 + 路径穿越校验） |

存储位置：`data/themes/<id>/theme.json` + `data/themes/<id>/assets/*`。
同名导入 = 覆盖（先删目录再写），所以「导出 → 再导入」是幂等的。

**zip 是自己实现的**（`server/src/themePack.ts`），没有新增依赖：只支持 `store` / `deflate` 两种压缩方式，
只读中央目录（不信本地头的大小），逐条验 CRC，解压走 `zlib.inflateRawSync` 并带 `maxOutputLength`。
Windows 资源管理器的「发送到 → 压缩文件夹」、`Compress-Archive`、macOS 的归档工具打出来的包都能导入；
我们导出的包也能被系统解压器正常展开（2026-10-19 实测双向通过）。

## 四、安全限制（硬性）

| 允许 | 禁止 |
|---|---|
| 改 token 数值/颜色、挑 variants、往 `assets/` 放图片 | 任何 CSS / JS / HTML / SVG |
| | 任何远程 URL（主题不联网） |
| | 主题包里的文件被当作代码执行 |

加载链路：**zip → 校验 → 归一化 → 写 JSON → 前端只读 token 对象 → 转成 CSS 变量**。
中间没有任何「把字符串当样式/脚本」的环节，所以不存在注入面。

## 五、三套内置主题

| 主题 | 定位 | 关键差异 |
|---|---|---|
| **胡桃木**（默认） | 典雅大气 | 宋体、2~6px 直角、无阴影、无装饰、200ms 淡入、印章 |
| **星弈·青** | 年轻群体 | 墨青夜（深青底 + 金线 + 紫光）、黑体、12~24px 大圆角、柔光、装饰层、320ms 弹性 |
| **竹青**（W4 新增） | 冷色低饱和 | 竹青纸底 + 墨绿 + 赭石印、6~14px 中圆角、1 级轻投影、260ms 不弹动 |

星弈·青不只是"给年轻人用"，更是主题系统的**压力测试**：如果它做不出来，说明 Token 不够深，得回头改架构。
竹青是反过来的一次测试：**不加任何装饰层**，只靠颜色与圆角，看 token 层够不够表达「清雅」。

两套内置主题的数据存在两份：

- `web/src/theme/skins.ts` —— 首屏同步可用（刷新页面时不等接口就知道用哪套）
- `data/themes/<id>/theme.json` —— 导出时服务端读这份

这两份由 `server/test/theme.test.ts` 的第一条用例逐字段比对守着：**改了其中一份而没改另一份，测试会红**。
新增内置主题时两份都要加，且 `SKINS` 里的 `builtin` 必须是 `true`。

## 六、字体

| 用途 | 字体 | 许可 |
|---|---|---|
| 标题 / 模式名 / 印章 | 思源宋体 Source Han Serif SC | SIL OFL 1.1 |
| 正文 / 数字 / 按钮 | 思源黑体 Source Han Sans SC | SIL OFL 1.1 |

字体**不随仓库分发**，用系统已安装版本；没装会回退到 `Songti SC` / `Microsoft YaHei` 之类。
安装方式：Adobe 官方 release 或系统包管理器；装完刷新页面即可。
主题包**不能**内嵌字体文件（只允许 json + 图片），字体要么用系统字体，要么用 `font` 里写字体族名。

## 七、做一个自己的主题

1. 复制 `data/themes/bamboo/theme.json` 到任意临时目录，改 `id`（小写字母/数字/`-`）和 `name`。
2. 改颜色：先定 `bg` / `surface` / `text` 三个，再定 `board` / `boardLine` / `blackStone` / `whiteStone`——
   棋盘这四色决定「能不能长时间看」，比 UI 配色重要。
3. **想让别人能用**：把目录压成 zip（`theme.json` 在压缩包根目录，或外面再套一层文件夹也行），
   在设置 → 主题里「导入主题包（zip）」。
4. 看得见的坑：`text` 与 `bg` 对比度不够会在浅色环境糊成一片；`boardLine` 太浅会导致棋子位置看不清。
   改完把主界面、对局页、设置页、结算页各走一遍（`docs/测试清单.md` 有清单）。
5. 想成为**内置**主题：改 `web/src/theme/skins.ts` + 加 `data/themes/<id>/theme.json`，跑 `npm test` 让两份对齐。

> 本版 `assets/` 只做「存取 + 保真导出」，界面还没有消费它们（棋盘贴图/装饰层等留到 P6 之后）。
> 现在往包里放图片是安全的，只是暂时看不到效果。
