# 引擎安装（KataGo）

星弈不内置引擎与权重，原因有两个：权重动辄上百 MB 不适合进 git；KataGo 与权重的许可证以官方发布页说明为准，随仓库分发不干净。

装一次，以后都能用。整个流程 10 分钟足够。

---

## 一、下载

| 东西 | 去哪 | 说明 |
|---|---|---|
| KataGo 程序 | <https://github.com/lightvector/KataGo/releases> | 按你的显卡选构建 |
| 主模型 | 官方 release 页里的 `kata1-b18c384nbt-*.bin.gz` | 18 层 Transformer，通用最强档 |
| human SL 模型 | KataGo **v1.15.0** release 里的 `b18c384nbt-humanv0.bin.gz` | 1~11 级必须用它，否则低段 AI 只会随机犯蠢 |

**选哪个程序**（这条很重要，选错了启动直接失败）：

| 你的机器 | 下载 | 后端 |
|---|---|---|
| NVIDIA 显卡 | `katago-vX.Y.Z-cudaXX.XX-windows-x64.zip` | CUDA |
| AMD / Intel 显卡、核显 | `katago-vX.Y.Z-opencl-windows-x64.zip` | OpenCL |
| 只有 CPU | `katago-vX.Y.Z-eigen-windows-x64.zip`（带 AVX2） | Eigen（很慢） |

> ⚠️ **待实测**：KataGo 从 v1.18.2 起官方只发 CUDA 构建；要找 OpenCL / Eigen 构建请用 v1.18.1 或更早。
> 如果下载页上找不到非 CUDA 包，就去 release 列表里翻旧版本。

解压到任意目录，例如 `D:\katago\`，里面应该有：

```
D:\katago\katago.exe
D:\katago\gtp_example.cfg
D:\katago\models\kata1-b18c384nbt-....bin.gz
D:\katago\models\b18c384nbt-humanv0.bin.gz
```

## 二、在星弈里填三步

打开星弈 → 设置 → 引擎：

1. **探测硬件**：会读显卡型号与显存，给出推荐后端。看不懂就用推荐值。
2. **katago 程序**：填 `katago.exe` 的完整路径。
3. **主模型 / human SL 模型**：填两个 `.bin.gz` 的完整路径。

然后点 **保存并自检**。自检会真的把引擎拉起来，依次检查：

- 文件存在
- 进程能启动
- `boardsize 19` + `clear_board` 能跑（说明模型加载成功）
- `kata-get-models` 能识别 human 模型（1~11 级有没有真实人类棋风就看这一项）

每一项都会给中文原因，不是 "engine init failed"。

配置文件一栏可以留空。留空时用星弈生成的最小参数启动；如果你想调 `numSearchThreads` 之类，就填官方 `gtp_example.cfg` 的路径。

---

## 三、显存不够怎么办

4GB 显存（例如 RTX 3050 Ti Laptop）同时加载主模型 + human 模型可能吃紧。降级顺序：

1. 先试一次完整配置，看设置页 `状态` 是否变成「就绪」
2. 不行就**先不填 human SL 模型**：能跑，但 1~11 级会退回"主模型低 visits"，棋风不像人
3. 还不行就换更小的模型（官方有 b10 / b6 之类的小网络），棋力略降、显存占用明显下降

> 待实测项：4GB 显存能否同载两个模型、3050 Ti 上的 visits/s。跑出来之后这里的建议会更新。

## 四、已知坑

| 现象 | 原因 / 处理 |
|---|---|
| 启动报错说找不到 CUDA / cuDNN | 下载了 CUDA 版但机器没装 CUDA 运行库。要么装 CUDA + cuDNN（版本要和构建匹配），要么换 OpenCL 版 |
| OpenCL 第一次启动卡几分钟 | 正常，KataGo 在做 tuner，之后会写缓存；AMD 卡异常时在 cfg 里加 `openclUseFP16 = false` |
| 12 级以上棋力感觉不对 | 加载了 human 模型后，星弈会尝试 `kata-set-param humanSLProfile ""` 切回主模型；若你的引擎版本不认这个写法，表现是"高段也不强"。**这一项目前待实测**，遇到请记下来 |
| 路径含中文 | Windows 下多数情况没问题，但个别构建对非 ASCII 路径敏感。出问题就把 katago 移到纯英文路径 |
| 端口被占用 | 星弈会自动顺延端口（7388 → 7389 …），启动日志里会打印实际端口 |

## 五、验证引擎真的在工作

装好后进「修习」，第一盘就是定级赛。如果：

- 印章下方出现对手等级
- 你落子后 AI 在 1~3 秒内应手
- 设置页显示「就绪 · v1.x.x」

说明整条链路通了。

想看协议层日志，启动服务时保持终端可见；引擎 stderr 会随 `stderr` 事件转发（目前只在服务端输出，界面上的日志面板在 P1 之后补）。

## 六、本机实测记录（2026-10-17，RTX 3050 Ti Laptop 4GB）

装的就是这一套，别人可以参考：

| 项 | 值 |
|---|---|
| 程序 | `katago-v1.18.2-cuda12.5-cudnn9.8.0-windows-x64.zip`（9.4 MB） |
| 主模型 | `b18c384nbt-uec.bin.gz`（93 MB，v1.12.4 release） |
| human 模型 | `b18c384nbt-humanv0.bin.gz`（94.5 MB，v1.15.0 release） |
| 驱动 | 616.92 |
| 引擎版本串 | `1.18.2+b18c384nbt-uec-20221121b+b18c384nbt-humanv0`（两个模型都在） |

### 没有装 CUDA Toolkit 也能跑 CUDA 版

本机没有 `nvcc`、没有 `CUDA_PATH`、`C:\Program Files\NVIDIA GPU Computing Toolkit` 也不存在，
但 **装过 PyTorch（cu126）** —— 它自带 CUDA 运行库与 cuDNN。把下列 DLL 从
`...\site-packages\torch\lib\` 复制到 `katago.exe` 同目录即可（不用装 3 GB 的 Toolkit）：

```
cudart64_12.dll  cublas64_12.dll  cublasLt64_12.dll
cudnn64_9.dll  cudnn_adv64_9.dll  cudnn_cnn64_9.dll  cudnn_ops64_9.dll
cudnn_engines_precompiled64_9.dll  cudnn_engines_runtime_compiled64_9.dll
cudnn_graph64_9.dll  cudnn_heuristic64_9.dll
nvrtc64_120_0.dll  nvrtc-builtins64_126.dll
```

> 注意版本要对上：KataGo 的 `cudnn9` 构建配 cuDNN 9.x；PyTorch 2.6 + cu126 正好是 cuDNN 9。

### benchmark 实测

```
katago.exe benchmark -model <模型> -config default_gtp.cfg -v 300
```

| 设置 | visits/s |
|---|---|
| 默认（6 线程） | ≈ 420 |
| 12 线程 | ≈ 460 |
| 12 线程 + 2 个 NN server 线程 + batch 6 | **≈ 540** |

写进 `xingyi.cfg`：`numSearchThreads = 12`、`numNNServerThreadsPerModel = 2`、`nnMaxBatchSize = 6`。

### 4 GB 显存够不够：够

主模型 + human 模型**同一个进程**同时加载，实测显存占用 **985 MB / 4096 MB**。
PLAN §15 的 R2（"4GB 装不下两个模型"）不成立——按需切模型那套降级链可以先不做。

### 一个必须知道的坑：human SL 默认不生效

只设 `kata-set-param humanSLProfile rank_8k` **不会改变 AI 的棋**。
原因是 `humanSLChosenMoveProp` 默认是 **0**，含义是"不从人类模型选点"。必须一起设：

```
kata-set-params {"humanSLProfile":"rank_8k","humanSLChosenMoveProp":1.0,"humanSLChosenMovePiklLambda":1e9,"humanSLChosenMoveIgnorePass":true}
```

切回主模型档位时要把 `humanSLChosenMoveProp` 设回 0 并清空 profile：

```
kata-set-params {"humanSLProfile":"","humanSLChosenMoveProp":0}
```

⚠️ 不要用 `kata-set-param humanSLProfile ""` —— 实测它会把值设成**两个引号字面量**，不是空串。
