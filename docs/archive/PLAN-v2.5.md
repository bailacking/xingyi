## 1. 项目定位

**一句话**：在本机跑 KataGo，做成一个"以练为主"的围棋软件——有升级模式的成长线、自由模式的完全放开、联机模式的真人对抗，外加教学、摆棋分析、可深度换主题。

**项目性质**：**开源个人项目**（GitHub，MIT），既自己日常练棋，也作为简历作品对外展示。

**由此带来的两条硬约束（贯穿全项目）**

1. **零版权风险**：题库、素材、音效必须能证明来源与授权。
2. **别人必须能跑起来**：不能假设下载者都有 NVIDIA 显卡。引擎与权重由用户自装，程序必须做**环境自检 + 引导**。

**非目标**

- 不做在线对战平台（不接 OGS/KGS/野狐）
- 不做通用 SGF 编辑器（只保证自家棋谱能正确导出/导入）
- 不做手机原生 App（手机走浏览器页面）
- 不做训练模型/自对弈
- 不做日本规则

## 2. 核心设计：三种模式

灵感来自 Minecraft 的生存/创造：**不是难度设置，而是三套规则世界**。

| | **修习**（升级 / 生存） | **自在**（自由 / 创造） | **手谈**（联机 / 多人） |
|---|---|---|---|
| 定位 | 有代价，有成长线 | 无代价，随便试 | 人对人 |
| 胜率/目差 | **强制隐藏**（控件置灰） | 开关 | 开关 |
| 每手点评 | **强制关** | 开关 | 开关 |
| 悔棋 | **禁止**（按钮置灰 + 说明原因） | 开关 | 开关（需对方同意） |
| AI 等级 | **锁定你的当前级** | 1~15 任选 | 无 AI |
| 摆棋分析 / 外部棋谱 | **不可用**（等于开卷考试） | 可用 | 不可用 |
| 进度 | **计入**（每盘都算） | 不计入 | 不计入 |
| 中途退出 | **算负** | 无影响 | 算负 / 超时 |
| 结算界面 | 胜负 + 连胜 + "已计入进度" | 完整数据 | 完整数据 |

**界面显示名**：**修习 / 自在 / 手谈**。文档内部仍按功能称"升级 / 自由 / 联机"，两者指同一模式。

**界面语言**：不做关卡地图。对局界面是**两枚印章**——你（印下刻 **陆级**）对 AI（印下刻 **难度 · 陆级**）。等级只在这里出现，一律用中文数字。

**架构要求（重要）**：模式是**能力门禁**，不是散落的 `if`。

```ts
type Mode = 'ranked' | 'free' | 'lan'
type Caps = {
  showWinrate: boolean; showComment: boolean; allowUndo: boolean
  allowAnalysis: boolean; allowImport: boolean; rankLocked: boolean
  countsToProgress: boolean; quitLoses: boolean
}
const CAPS: Record<Mode, Caps> = { ... }
```

所有 UI 控件读 `CAPS[mode]`，**置灰而不是隐藏**，并给出"升级模式不允许悔棋"这类说明。以后加模式只改一张表。

## 3. 评级系统（升级模式的引擎）

### 3.1 为什么不能"赢一盘升、输一盘降"

简单胜负计数有三个必死病：① 赢一盘升输一盘降（抖动）；② 胜率卡 55% 永远上不去（卡死）；③ 高手第一次进来要从 1 级爬（劝退）。

### 3.2 模型：Glicko 式连续评分

玩家有隐藏评分 R（初始 **1500**）与不确定度 RD（初始 **350**）。15 个 AI 等级各有校准分 A₁…A₁₅。

```
期望胜率  E = 1 / (1 + 10^((A_k − R) / 400))
评分更新  R += K_eff × (S − E)
目差修正  K_eff = K × (0.8 + 0.4 × min(|目差|/20, 1))
```

- `S` 是实际结果（胜 1 / 负 0）
- **K 随 RD 变化**：RD 大（新号、刚打完定级赛）→ K 大 → 连赢几盘评分飙得远。**"高手自动跳档"不需要额外规则，是这个公式的自然结果。**
- 目差只微调幅度（大胜 K 大 20%，微胜 K 小 20%），**不做"赢 20 目算 0.9 盘"的折算**——那样用户永远搞不懂为什么升不上去。

### 3.3 定级赛（3 盘自适应二分）

| 盘 | 对手 |
|---|---|
| 1 | 8 级 |
| 2 | 赢 → 12 级；输 → 4 级 |
| 3 | 按前两盘结果插值（连胜继续上探，连败下探） |

3 盘收敛到 ±2 级以内。**高手第一次进来不会从 1 级爬。**

**前 10 盘标记为"暂定级"**，K 值放大一倍（Glicko 的标准做法）。界面显示"暂定 6 级"，10 盘后转正。3 盘定级运气成分太大，靠前 10 盘收敛。

### 3.4 升降级判定

| 动作 | 条件 |
|---|---|
| **升级** | `R ≥ A_{k+1} − 50` 且 本级已下 ≥3 盘 且（连胜 ≥2 或 本级胜率 ≥60%） |
| **跳档考核** | 连胜 ≥3 且 `R ≥ A_{k+1} − 50` → 结算页底部出现一行小字「可进一级」；点它即对 k+1 或 k+2 级开一局，赢则跳 1~2 级 |
| **降级** | 保级期已过 且 `R < A_{k−1} − 100` 且 连败 ≥2 |
| **保级期** | 升入新级后 **3 盘内不降级** |
| **退级缓冲** | 降级后 5 盘内不连续降第二次 |

**为什么跳档要"考核局"而不是直接跳**：直接跳会让人莫名其妙连升两级；考核局顺便区分"真强"和"运气好"。考核失败不降级，但要冷却 3 盘才能再发起。**全程不弹窗、不庆祝、不换对手头像**——只管下。

### 3.5 防刷

| 手段 | 规则 |
|---|---|
| 同级重复对战 | 同一级超过 8 盘后，每多一盘 K × 0.5 |
| 速胜 | 总手数 < 40 手的对局按 `S = 0.5` 计 |
| 中途退出 | 算负（升级模式） |

### 3.6 满级之后

15 级 = **满级**，定位业余强手（主模型限 3000 visits，约 5d~7d）。满级后可无限刷 15 级、记录胜率。

> **注意**：15 级不是"本地最强"。KataGo 不限时全力是超人类（强于职业九段），但那不在 1~15 级评价体系里。
> **级数上限必须写进配置**（`config.json: maxLevel = 15`），不硬编码——几年后真要扩到 20 级，改配置即可。

### 3.7 存档

`progress.json`：当前级、评分 R、RD、暂定级标记、各局记录、连胜、跳档冷却。

- 每次写盘前留一份 `.bak`
- 带 `schemaVersion`，以后改结构能迁移
- 不做防作弊校验（单机游戏本来就能改存档，不值得做）

## 7. 引擎集成

### 7.1 三后端（发布版必须全支持）

| 后端 | 适用 | 配置差异 |
|---|---|---|
| CUDA | NVIDIA 显卡 | 需配套 CUDA + cuDNN（版本配对【待实测】）；可用 fp16 |
| OpenCL | 任意 GPU / 核显 | 首次启动自动 tuner 可能数分钟；部分 AMD 要 `openclUseFP16=false` |
| Eigen | 纯 CPU | AVX2 版；**极慢**，需在界面明确提示 |

**启动流程**：探测硬件 → 推荐后端 → 检查 katago 路径 → 发 `name`/`version`/`kata-list-params` 自检 → 显示"就绪 + visits/s"或明确报错。首次运行见 §18.1。

### 7.2 需要的东西（用户自装）

| 项 | 内容 |
|---|---|
| 二进制 | KataGo 官方 release（v1.18.2 起只出 CUDA；OpenCL/Eigen 用 v1.18.1 兼容构建）【待实测】 |
| 主模型 | `b18c384nbt` 系（Transformer） |
| 人类模型 | `b18c384nbt-humanv0.bin.gz`（v1.15.0 release） |
| 配置 | 三个模板：`gtp_xingyi_cuda.cfg` / `_opencl.cfg` / `_eigen.cfg` |

**为什么不能只用主模型**：低段难度若用"低 visits 的主模型"，行为是随机犯蠢，不像人。human SL 是拿真实人类对局学的。

### 7.3 GTP 封装要点

- spawn 子进程，行读写；请求带自增 id
- **请求队列串行**，一条响应没回来不发下一条
- `kata-analyze` 是**异步流**：持续输出，收到任何新命令即终止 → 新请求必须先打断旧流
- interval 单位是**厘秒**
- 超时兜底 + 进程退出重启 + 重建局面（`boardsize`/`komi`/逐手 `play` 回放）
- 引擎状态可见（未配置 / 加载中 / 就绪 / 思考中 / 已崩溃）

### 7.4 分析数据（全部现成）

`kata-analyze <color> interval <cs> ownership true`：

| 字段 | 用途 |
|---|---|
| `move` / `order` | 候选点、排序 |
| `visits` | 置信度 |
| `winrate` | 胜率 |
| `scoreLead` | 领先目数（对初学者比胜率有用） |
| `prior` | 先验（可选显示） |
| `pv` | 主变化，点候选预览后续几手 |
| `ownership` | 361 点归属 [-1,1]，行主序 A19→T1 → 形势图 |

### 7.5 摆棋模式必须显式处理的参数

| 参数 | 为什么 |
|---|---|
| `analysisIgnorePreRootHistory true` | 摆子局面无落子历史，不关会变慢/出怪结果 |
| `playoutDoublingAdvantage` | 控制"假设对手比我弱/强"，摆棋练习必调 |
| `maxVisits` | 与"快速/标准/深算"三档绑定 |

**界面上要有「假设对手水平」滑杆**——这是摆棋分析和"看 AI 下棋"的本质区别。

## 10. 功能规格

### 10.1 自由模式（P1：摆棋分析）

| # | 功能 | 验收 |
|---|---|---|
| 1 | 自由摆子 | 9/13/19 路；摆黑白、擦子、标死子 |
| 2 | 悔棋/重做 | 任意步数，摆子本身可撤销 |
| 3 | 实时推荐 | 局面变化后 ≤300ms 出 top5，含目差 |
| 4 | 变化预览 | 点候选叠出后续 5 手（幽灵子） |
| 5 | 形势图 | ownership 叠色（黑方深蓝 / 白方暖橙），可开关，透明度 ≤35% |
| 6 | 目差曲线 | 沿主分支走势 |
| 7 | 一键落子 | 点推荐标记直接落 |
| 8 | 防抖 | 连续摆子只算最后一次 |
| 9 | 假设对手水平 | 滑杆调 `playoutDoublingAdvantage` |
| 10 | 引擎容错 | 崩溃重启并告知原因 |
| 11 | 导入外部 SGF | 拖拽即开；变体分支要正确还原 |
| 12 | 沿分支分析 | 逐手胜率/目差曲线，可跳任意手 |

**P1 不做**：完整变化树的可视化编辑、多分支对比、批量棋谱分析。

### 10.2 自由模式（P2：对 AI 下棋）

- 任意选 1~15 级、任意棋盘尺寸、让子、贴目、计时
- 三开关（胜率/点评/悔棋）默认全关
- **悔棋 = 任意步数 + AI 重算**
- AI 思考期间**锁棋盘**；分析请求排队合并
- 结束 → 复盘：逐手标 好/一般/失误（`scoreLead` 差值），并标着法名称
- 结果存 SGF（不计入升级进度）

### 10.3 升级模式（P3）

- 对局界面 = **两枚印章**：你（印下「陆级」）对 AI（印下「难度 · 陆级」）
- **对当前级 AI 下棋**，每盘计分（D38）
- 不可悔棋、不显示胜率点评、不可用分析与导入（控件置灰 + 说明）
- 退出 = 算负
- 结算：胜负 + 「三连胜」纯文字 + 「已计入进度」；跳档条件满足时底部一行小字「可进一级」（见 §11.4）
- 输棋自动进复盘（可跳过）
- 定级赛 3 盘 + 前 10 盘暂定级
- 跳档考核：连胜 ≥3 时提示，接受后对高 1~2 级下一盘
- 满级后无限刷 15 级记胜率

### 10.4 教学 + 题库（P4）

- 规则教学：**可交互跟做**（每步落对了才进下一步）
- 定式练习：不在树内**不判错**，给黄色提示 + 亮 AI 推荐
- 死活题：先比答案坐标，不匹配再让 AI 判死活
- 题目测级：固定 10 题，可手动改定级

### 10.5 联机模式（P5）

- 房主起 WS 服务，显示 6 位房间码 + IP + 二维码
- **局域网自动发现**：同网段打开软件就能看到在等的人
- 手机扫码加入；手机端只给 下棋 / 聊天 / 看谱
- **不共享 AI 推荐**（D27）
- 观战 + 聊天（聊天不入库）
- 落子同步、悔棋需同意、认输、断线重连、超时判负
- **不计入升级进度**（D43）

### 10.6 主题系统（P6）

- 主题包 = 文件夹/zip：`theme.json`（tokens + variants）+ 可选 `style.css` + 素材目录
- **深度个性化**：颜色、圆角、阴影、密度、动效强度、装饰层、字体、组件变体、玩家标识形态
- 内置两套做深：**胡桃木（典雅，默认）** + 一套年轻化（见 §11.10）
- 导入导出 zip；**禁止 JS**，禁远程 URL（见 §11.9）
- 素材只用 **CC0**；音效落子/提子/磬，主题可替换

## 11. 视觉与主题系统

**原则**：下棋是高雅娱乐，不是激励游戏。**没有礼花、没有连击特效、没有音效轰炸。**界面要像一间书房：留白、克制的颜色、器物感。

### 11.1 色与形

| 项 | 规范 |
|---|---|
| 底色 | 米白 `#F7F4EE`（宣纸感） |
| 主色 | 深胡桃木 `#3E2C20` |
| 强调 | 细金线 `#A98C5F`，**只用于分割线与选中态**，不做大面积 |
| 文字 | 主 `#2A2622` / 次 `#6B625A` |
| 圆角 | 2~4px（器物是直角，不用大圆角） |
| 阴影 | 只留极淡一层（棋盘木托）；不做发光、不做毛玻璃 |

### 11.2 字体与等级写法

- 标题 / 模式名 / 印章：**思源宋体**（SIL OFL）
- 正文 / 数字 / 按钮：**思源黑体**（SIL OFL）
- 等级用中文数字：**正文写「六级」，印章内用大写「陆级」**（一寸见方的印，用大写才像印）
- 「十五级」三字最长，按钮与印章要做宽度自适应

### 11.3 落子与动效

- 落子：直接出现，**无缩放、无弹跳**；只有一声实响与一次极淡阴影
- 切页：200ms 淡入
- 形势图：300ms 淡入，不做"扫过"动画
- 音效：落子、提子、终局一声磬。**不做读秒声**，读秒只在界面角落淡入数字

### 11.4 结算页与跳档

```
白中盘胜
三连胜
已计入进度
                可进一级 →      ← 仅条件满足时出现的一行小字
```

**不弹窗、不庆祝、不换"考官"头像。**点「可进一级」直接开下一局。

### 11.5 主界面

一屏只有四行，从上到下：

```
星弈
修习   自在   手谈
设置
退出
```

不放统计、不放最近对局、不放进度条。

### 11.6 手机端

同一套视觉，纵向堆叠：棋盘占上半屏，信息在下。印章缩成小印，不做大图。

### 11.7 主题 = Token + 组件变体

主题**不重写界面**，只做两件事：

1. **改 Token**：颜色、圆角、阴影、间距、字号、动效强度、装饰层
2. **挑变体**：从预置的组件家族里选一套

新增功能只写基础组件 → 主题自动继承，**不需要为每套主题重做一遍**。这是能在一个人维护的前提下做到"深度个性化"的唯一办法。

**Token 表**（`theme.json` 的 `tokens` 段）

| Token | 胡桃木（典雅） | 年轻化主题 |
|---|---|---|
| `color.bg` | `#F7F4EE` | `#2B1E3A` |
| `color.surface` | `#FFFFFF` | `#3A2A4D` |
| `color.primary` | `#3E2C20` | `#B45CFF` |
| `color.accent` | `#A98C5F` | `#FF7AB6` |
| `radius.sm/md/lg` | 2 / 4 / 6 px | 12 / 16 / 24 px |
| `shadow.level` | 0（几乎无） | 3（柔光） |
| `density` | comfortable | compact |
| `motion.speed` | 200ms | 320ms |
| `motion.bounce` | false | true |
| `font.title` | 思源宋体 | 思源黑体 Bold |
| `decor.layers` | `[]` | `["glow","particles"]` |
| `playerMark` | `seal`（印章） | `avatarCard`（立绘卡） |

**组件变体**（`theme.json` 的 `variants` 段，只能选、不能造）

| 组件 | 可选变体 |
|---|---|
| 按钮 | `flat`（典雅）/ `soft`（柔光）/ `glow`（年轻） |
| 面板 | `paper`（纸面）/ `glass`（毛玻璃）/ `solid`（实色） |
| 玩家标识 | `seal`（印章）/ `avatarCard`（立绘卡） |
| 结算 | `plain`（一行字）/ `card`（卡片） |

### 11.8 主题包结构

```
my-theme/
├─ theme.json        tokens + variants + 元信息（名称/作者/版本）
├─ style.css         可选，特殊效果（禁 JS）
├─ board/            棋盘图、棋子图
├─ sound/            落子 / 提子 / 磬
└─ decor/            装饰层素材（光斑、粒子、花纹）
```

导入导出就是一个 zip。**不做在线市场**（D59）。主题目录里的 `.js` 文件一律拒绝加载并提示。

### 11.9 CSS 限制与安全

| 允许 | 禁止 |
|---|---|
| 自定义属性、过渡动画、滤镜、伪元素、背景图 | `@import`、任何远程 URL、JS |

理由：远程 URL 会让"离线可用"变成假话，也是隐私泄露的口子；JS 在开源软件里等于把执行权限交给随便一个主题包。

加载前用 schema 校验 `theme.json`，**不认识的字段忽略而不是报错**——这样旧版本软件打开新主题不会直接崩。

### 11.10 两套内置主题

| 主题 | 定位 | 关键差异 |
|---|---|---|
| **胡桃木**（默认） | 典雅大气 | 宋体、2~6px 直角、无阴影、无装饰、200ms 淡入、印章 |
| **星弈·青** | 年轻群体 | **墨青夜**（深青底 + 金线 + 紫光）、黑体加粗、12~24px 大圆角、柔光渐变、装饰层、320ms 弹性、立绘卡 |

第二套不只是"给年轻人用"，更是**主题系统的压力测试**：如果它做不出来，说明 Token 不够深，得回头改架构。

### 11.11 角色系统（预留，不在 v1 范围）

立绘、台词、表情、语音是"雀魂感"的核心，但它属于**功能**而不是**皮肤**——涉及对局中的触发时机、音效混音、素材版权。

- 现在不做（D61）
- **架构留位**：对局界面 AI 一侧预留 `characterSlot`，现在放印章，将来可换立绘卡
- 引入判据：主题系统与对弈流程稳定之后（P7 之后）

### 11.12 主题预览

主题选择页每个主题给一张卡片，卡片内是**实时渲染的微型界面**——不用静态截图，因为截图会随版本过期。

```
┌──────────────┐
│  星弈        │  ← 上半：缩小的主界面（标题 + 三入口）
│  修习 自在 手谈│
├──────────────┤
│  ·  ·  ·  ·  │  ← 下半：一局对弈的定格（棋盘 + 两枚标识 + 信息栏）
│  ·  ●  ·  ·  │
└──────────────┘
```

- 鼠标悬停：动效播放一次（一次落子、面板浮起），让你感受"手感"
- 点「应用」：整站切换，**5 秒内可撤销**（底部浮一条"已切换到星弈·青 · 撤销"）
- 技术：预览卡片把 `ThemeProvider` 套在固定尺寸容器里，内部用 mock 数据渲染，**不连引擎、不发请求**

### 11.13 性能、屏幕与窗口

| 项 | 规定 |
|---|---|
| 窗口 | **默认最大化**（不遮盖任务栏）；最小 1024×700；棋盘随窗口缩放并保持正方形 |
| 性能档 | 启动后测 3 秒平均帧率：< 45fps 自动关装饰层与毛玻璃；设置里可手动锁定"高效 / 全效" |
| 形势图 | 黑方深蓝 / 白方暖橙；**透明度上限 35%**，否则会盖住棋子颜色 |
| 高分屏 | 按 `devicePixelRatio` 渲染棋盘，避免 Windows 125% / 150% 缩放下棋子发虚 |

## 18. 运行与维护

### 18.1 首次运行向导（三步）

| 步 | 做什么 | 当场校验 |
|---|---|---|
| 1 | 选后端 | 探测 GPU 型号与显存，推荐 CUDA / OpenCL / Eigen，并说明各自速度差异 |
| 2 | 指 `katago.exe` | 文件存在、可执行、能跑 `version`；**版本与所选后端是否匹配**（"这个 exe 是 OpenCL 版，但你选了 CUDA"） |
| 3 | 指两个模型 | 文件存在、体积合理、能加载（发 `boardsize` + `clear_board` 验证） |

失败一律给**中文原因 + 下一步该怎么做**，不说"engine init failed"这种话。可跳过；设置里能重跑。

### 18.2 版本更新

启动时静默请求 GitHub Release API（超时 3 秒，失败静默，不报错、不打扰）。有新版本只在「设置」里出现一个小标记，点开是版本号与更新说明链接。**不自动下载、不自动安装**（D71）。

### 18.3 存档与备份

| 时机 | 动作 |
|---|---|
| 每次写 `progress.json` 前 | 旧文件复制为 `progress.json.bak` |
| 每天首次启动 | 复制到 `backups/progress-YYYYMMDD.json`，最多留 10 份 |
| 用户点「导出进度」 | 生成 zip（`progress.json` + 对局索引），可换机器导入 |
