# 已知问题（BUG 登记表）

> 修 BUG 窗口的唯一登记处。**一个 BUG 一行，修完把状态改成「已修（commit）」并写一句根因。**
> 不要在这里记「想法」或「待优化」——那些属于 `docs/并行开发计划.md` 的任务卡。

## 0. 修复纪律

1. **先复现，再改代码**：先把「复现步骤」写成别人照着能重现的三五步；复现不了就先补日志，别猜。
2. **一次只修一个 BUG**，一个 commit；标题 `fix(<范围>): <现象>`，正文写根因。
3. **不顺手重构**：不重命名、不调整目录、不改公共类型/接口/数据格式。真需要，先在这里记一条「需要拍板」。
4. **能加回归测试就加**（规则、服务端、数据类必修；纯样式问题可只截图）。
5. 改完必须：`npm test`（168 项）+ `npm run typecheck` 全绿，再推送。
6. 修完顺手看一眼 `AGENTS.md` §15「已踩过的坑」——同一个坑别踩第二次；新坑补一行进去。

> **B-001 / B-003 根因（同一处）**：`web/src/board/Board.tsx` 的点击区写成
> `if (interactive && grid[v] === 0) onPlace(v)`——有子的格子直接被吞。
> 摆棋的「擦/改色」正是要点已有子（B-001），对局里点重复点则应该由规则层回中文禁着（B-003）。
> 修法：点击区不再自己判空，`interactive` 时一律交出去；摆棋按调色板处理，对局由服务端回
> 「该点已有棋子」——合法性判定只留规则层一处（§6 I4）。
> 验证：无头浏览器「落子 → 切擦 → 点回」子数 1 → 0；「落子 → AI 应手 → 再点同一点」
> 侧栏出现「该点已有棋子」；页面无 JS 错误。
>
> **B-003 补刀**：提示原来挂在侧栏最底部，1440×900 下实测 `top=996 > innerHeight=900`，
> 也就是**提示存在但看不见**，等于没修。现在把错误条挪到侧栏顶部（`top=18`）。
> 以后加提示类 UI，量一下 `getBoundingClientRect().top` 再算修好。

> **B-002 根因**：`server/src/api.ts` 的 `/api/game/:id/sgf` 没给 `toSgf` 传 `handicap`
> （`saveSgf` 那条路径传了，所以自动存的谱是对的、手动导出的不对）；`parseSgf` 也从未读 `HA`。
> 修法：导出补 `handicap`；`parseSgf` 增加 `handicap` 字段（只认 2~9）；`importSgf` 仅在
> 盘上真有 ≥2 颗黑子时才认这个数，避免「显示让 N 子却空盘」。
> 验证：让 0/3/9 子各导出再导入，`HA[3]`/`HA[9]` 正确、回导 `handicap` 与贴目、白先一致；
